# Concept B: シンプルでモダンな UI

- Section: `9:9`（Concept B シンプル(OpenCode)）
- Figma: https://www.figma.com/design/cENMDi4g6IiBx79io0kOil/?node-id=9-9
- 使用フォント: Noto Sans JP（Regular / Medium / Bold。`listAvailableFontsAsync` で確認済み）
- 状態: Figma ボードはホーム PC/SP・資産管理 PC/SP の4件のまま（本 PR では Figma に書かない）。HTML+PNG で 6 画面＋ダーク 1 枚を揃えた。詳細は §10。

## 1. 名前・理念

**名前: シンプルでモダンな UI — 「余白と一貫性で見せる」**

理念: 証券 Web の利用者の多くは毎日見ないライトユーザーであり、開いた瞬間に「いくらあるか・何が起きたか」だけ分かればよい（根拠: Phase 1 のホーム・資産管理・取引明細の撮影画像で、主要値は評価額・評価損益・受取配当の 3 点に集約できることを確認）。Concept B は情報を削るのではなく、**装飾（円グラフ・多色・達成率バー）をやめ、余白・単色のバー・固定順序の集計帯に置き換える**ことで、初見でも迷わない画面にする。派手さより「どこを見ればよいか分かること」を優先する。

## 2. ビジュアル

### 色

- ブランドは維持する（紺ヘッダー `#0F2A4A` / 紺の集計帯・橙のアクセント金 `#F2B33D`）。理由: 「証券 Web」の識別子であり、Phase 1 画像でヘッダー・帯の紺はライト/ダーク共通の目印になっている。変える理由がないため変えない。
- 金の用途を「選択中の下線・グループ行の左線」の 2 か所に限定する（現状はチャート・バッジ・バーにも分散。根拠: `home-default-pc-dark.png` でダークの配当カードが橙/青に見え、ライトと色の意味が変わって見える）。
- グラフは単色系に統一する。達成系＝アクセント `#1D4ED8` の単色、前年比較＝グレー系。内訳系＝アクセントの濃淡段差。系列色 `chart-1..5` の使い分けをやめ、色数で意味が変わらないようにする。
- 損益は既存トークンのまま: 正＝ `#0B7A4b` 系（`positive`）、負＝ `#C0362C` 系（`negative`）。符号（+/−）と色を必ず併用し、色だけにしない（`frontend/README.md` のアクセシビリティ決まりによる）。
- ダークは既存 `@theme` の反転定義をそのまま使う（`input.css:217-`）。新規トークンを増やさず、面・文字・罫線の反転に乗る。

### 文字

- Noto Sans JP。見出し 20px Bold / カード見出し 15px Bold / 本文 13〜14px Regular / 注記・凡例 11〜12px Regular / 集計帯の主額 26〜30px Bold（PC）・30px（SP は現状の `text-summary-primary` 準拠）。
- 数値は `tabular-nums`＋`whitespace-nowrap`（`ui/amount.rs` の `Amount` が保証）。桁区切り・符号・単位の付け方は `ui/format.rs` に一本化し、画面ごとに書式関数を作らない。

### 余白

- 8pt グリッド。カード間 16px、カード内 16〜20px、行の器は左右 16px・上下 12px＋区切り線（`mobile-ui-rules.md` の「行」と同じ）。
- 帯・タブ・行は画面端まで敷き、文字だけ 16px（`page-gutter` の重ね置き禁止を維持）。

### 角丸・影

- カード＝ `rounded-xl`（12px）＋ `shadow-elevation-1`、入力・検索＝ `rounded-lg`（8px）、バッジ・タブ・「予想の N 倍」札＝ `rounded-full`。影は浮き面だけに使い、本文の区切りは罫線で付ける（影の多用はノイズになるため）。

### アイコン

- アイコンのみのボタン禁止（`ui-design.md:15`）。操作は必ず文字ラベル付きにする。開閉は山形＋「開く/閉じる」文言（`ui/disclosure.rs`）。虫眼鏡・矢印などの装飾アイコンは現状のまま増やさない。

## 3. 情報設計

### ナビゲーション

- 現状の型を維持する。上バー（ページ名＋低頻度リンク＋アカウント）→ タブ（種別切替、全幅下線）→ 集計帯 → 注記行 → 検索入口 → 一覧（行/グループ行）→ フッター → 下部ナビ（SP）。順番は変えない（`mobile-ui-rules.md` の「画面の型」による）。
- 構成比への入口は件数行の右 1 か所に統一する（PC 上バーの重複ボタンをやめる。根拠: Phase 2 X-2/CO-2）。

### 集計帯

- 全タブで項目の順序を固定し、タブ固有項目は末尾に足す（根拠: Phase 2 AS-2）。例: 資産管理＝評価額・評価損益・前日比・取得総額の順で固定。国内株式タブの年間配当・利回りは末尾追加。
- 時点ラベルを分離する。価格の時点は `価格基準日 2026/10/20`（年付き）、取込時点は `データ: 2026/1/1 取り込み` の 2 ラベルに分け、年なしの `10/20` 表記をやめる（根拠: Phase 2 Codex-1）。チャート見出しには対象期間 `2026/01 〜 2026/12` を添える（根拠: Phase 2 HO-4）。

### 一覧

- PC 表は名称列を最広にし、ファンド名は省略（`…`）せず 2 行まで表示する。3 行以上は行詳細・銘柄詳細で全文確認（根拠: Phase 2 Codex-3/AS-1）。
- 金額列は右揃え・桁区切り・符号＋色・欠測 `—` で全画面統一（現状良好＝Phase 2 X-4。維持）。
- 取引明細の一覧は主要値（配当＝税引後受取額、株式・投信＝税引後損益）を強調し、補助値（税引前・税額）は列グループ化して整列させる（根拠: Phase 2 Codex-4）。SP 行の 2 段目に税額の目安を足すかは密度とのトレードオフのため Phase 4 で A/B 判断する（現状は DetailDialog 維持）。
- グループ小計行のラベルは `2026年12月 ｜ 3件の合計` の形にし、帯の集計との関係を文言で明示する（根拠: Phase 2 RE-3）。

### 詳細

- 行を押したときの振る舞いは現状維持（保有物＝詳細画面へ、出来事＝ダイアログで開く、その場展開なし。`mobile-ui-rules.md` による）。
- モバイル詳細は画面下シート（`DetailDialog`）、PC は中央ダイアログ。詳細内の項目順は PC 列順と揃える（根拠: Phase 2 Codex-4）。

## 4. 操作性

- 主要操作は 2 タップ以内・頻繁な操作は常時表示（`ui-design.md` 維持）。
- 検索・並べ替え入口は SP では「検索・並べ替え」ボタン 1 つにまとめ、シートで操作する。銘柄検索だけ下部操作帯（例外規定を維持）。
- 条件パネルを開いたら表側を非活性化していることが分かるよう backdrop を濃くする（根拠: Phase 2 RE-2）。
- 空状態は「登録/取込」の次の行動、失敗は「再読み込み」を共通部品・共通位置で出す。説明文は 1〜2 行に揃える（根拠: Phase 2 Codex-8/X-3）。
- タップ領域は SP 44px 以上・入力文字 16px 以上（`frontend/README.md` による）。フォーカスは可視枠を付け、外観だけで伝えない。

## 5. 視認性

- コントラスト比 4.5:1 以上を満たす既存トークンのみ使う（`text-faint` は薄い補助に限定。新規の薄色を作らない）。
- 月別棒グラフは値 0 の月を省略して「入金なし」と注記し、凡例は色＋年ラベル（実線/ Outline の形差）で色のみに依存しない（根拠: Phase 2 HO-1/HO-3）。
- ホーム配当バーは上限で止め、超過分は `予想の 16.1 倍` の文言で出す。1611% のような 4 桁 % は出さない（根拠: Phase 2 H-1）。
- 円グラフを廃止し横バーに統一する。凡例の省略（`…`）をなくし、名称＋割合を同じ順序・同じ値表記で並べる（根拠: Phase 2 Codex-5/HO-2/CO-1）。
- CSV 状態は「状態名＋最終取得時点」の 2 項目表示にし、日付形式を `YYYY/M/D HH:MM` に統一する（根拠: Phase 2 Codex-6/CSV-1）。
- ブラウザ/OS 名は短い表示名に正規化し、全文は詳細に隠す（根拠: Phase 2 Codex-7/ST-2）。
- 長いメールは省略＋ `title`/コピーにする（根拠: Phase 2 AD-1）。

## 6. 利用者・場面

- 月 1〜数回開くライトユーザー（配当の入金確認・資産の概況把握）が主対象。初見でも「評価額→損益→配当」の順に目線が流れる。
- 高頻度トレーダー・多銘柄比較には向かない（高密度の Concept A が担当）。Concept B は「迷わないこと」を選び、比較効率は Concept A/C に譲る。
- SP 片手操作・屋外の低コントラスト環境・ダーク利用を想定し、タップ領域と文字サイズを優先する。

## 8. 長期の拡張性

- 新規トークン・新規部品を作らないため、将来の画面追加は既存 3 部品（`SummaryBand`・`ListRow`・`DetailDialog`）の組合せで足りる。新規パターンは `mobile-ui-rules.md` の例外表に追記して管理する。
- チャートを単色バーに寄せたため、系列追加（商品別・口座別の細分化）は濃淡段差の追加だけで対応でき、色設計の衝突が起きない。
- 帯の項目順固定により、将来の指標追加は「末尾追加」の 1 ルールで済み、タブごとの分岐が増えない。

## 9. Phase 2 の課題への対応（課題ごとに 1 行）

Codex 監査（`ux-audit-codex.md`）：

- Codex-1（時点が短い日付だけ）: 価格基準日は年付き・取込日と別ラベルにし、全画面で統一する。
- Codex-2（ホーム SP 上部が他と異なる）: ホームも共通の帯規則に寄せ、評価額・評価損益・配当サマリーの優先順と開閉対象を固定する。
- Codex-3（長い銘柄名の省略）: PC は名称列を最広＋2 行表示、SP は折返し許容＋優先情報固定で全文到達可能にする。
- Codex-4（明細の密度と役割曖昧）: 一覧は主要値強調＋補助値の列グループ化、詳細は PC 列順と同順にする。
- Codex-5（構成比ラベル切れ）: 円グラフ廃止→横バー化し、凡例は短縮名＋割合を順位一覧と同順・同表記にする。
- Codex-6（CSV 状態が色と時刻依存）: 状態名と最終取得時点を別項目・年付き日付に統一し色だけにしない。
- Codex-7（長いブラウザ名）: 短い表示名に正規化し全文は詳細操作に隠す。
- Codex-8（空・エラー後の行動差）: 空は登録/取込・失敗は再読み込みを共通部品・共通位置で出し説明は 1〜2 行にする。

## 11. Devin 指摘への対応と数値の型統一

- 指摘（PR #1897 の inline コメント）: 取引明細モックが配当に `pos`・税額に `neg` を付けているが、`frontend/README.md:167` の「税額・配当・利回りは色なし」・「プラスに符号なし」と食い違う。
