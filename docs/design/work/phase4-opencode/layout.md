# PC・スマホのレイアウト規則(Phase 4・OpenCode)

- 採用方針: C を骨格にし、B のスマホの作りと A の PC 詳細パネルを取り入れるハイブリッド(`design-decision-p3.md:17-23`)。縦ナビは採用しない。円グラフ廃止(横バー化)・曲線グラフは見送り。
- 対応づけの正本: 骨格は `frontend/src/ui/page_skeleton.rs`(`SkeletonTabs`・`SkeletonSummary`・`SkeletonNote`)、枠は `frontend/src/ui/page_frame.rs`(`PageFrame`)、帯は `frontend/src/ui/summary.rs`(`SummaryBand`)、行は `frontend/src/ui/list_row.rs`(`ListRow`)、下部ナビは `frontend/src/ui/site.rs`(`BottomNav`)。新しい部品名は作らない。
- 画面の要件の正本は `docs/ui-design.md`、スマホの組み立ては `docs/design/mobile-ui-rules.md`。本書は Phase 4 の幅別規則と画面ごとの配置を決め、`mobile-ui-rules.md` との差分を表にする。

## 1. 画面の型(部品の順序)

ログイン後の画面は上から次の順に組み立てる。使わない段は飛ばしてよいが、順番は変えない(`mobile-ui-rules.md:18-33` の型を PC にも適用する。PC とスマホで順序を変えない)。

```text
上バー(ページ名 [件数] … [低頻度リンク] [アカウント])
[戻る]                        ← 詳細画面だけ(PageFrame の back_href)
タブ                          ← 種別を切替える画面だけ(SkeletonTabs + .page-tab)
集計帯 / 要点カード            ← 数値を集計する画面だけ(SummaryBand を SkeletonSummary に入れる)
注記行                        ← 出す文があるときだけ(SkeletonNote。時点・対象外・絞り込み中+「計算基準を見る」)
検索入口                      ← 一覧を絞れる画面だけ(SkeletonSearch + 共通の入口部品)
一覧(行・グループ行)/ 詳細 / フォーム
──── ページの末尾 ────
フッター
下部ナビ(ホーム|資産管理|取引明細|銘柄検索)  ← スマホだけ。PC は出さない
```

### 1.1 各型の決まり

| 型 | PC(1280〜1920) | スマホ(390) | 対応部品 |
|---|---|---|---|
| 上バー | ロゴ+グローバルナビ(ホーム/資産管理/取引明細/銘柄検索)+アカウント。ページ名(h1)は 1 つだけ。本文と同じ幅(`page-gutter`/`content-gutter`) | 紺の帯(`PageFrame` の見出し)。ページ名+件数(`title_count`)だけ。右端は低頻度リンク→アカウントの順 | `ui/page_frame.rs` `PageFrame`、`ui/site.rs` `SiteHeader`、`app.rs` の表示判定 |
| 集計帯 / 要点カード | 紺帯は角丸+グラデーションの 1 行(`input.css:943-966`)。主値(税引後)を先頭に、項目は `summary-item` で横並び。ホームの要点カードは `home-card-row`(PC 2 列) | 全幅・角丸なしでページと一緒に流れる(張り付かない)。主 1 つ+補助 1 行。開閉は帯全体を押す | `ui/summary.rs` `SummaryBand`・`SummaryItem`(`Primary`・`Secondary`、`Neutral`・`Gain`・`Loss`) |
| タブ | 枠つきピル型 3 列(`page-tab-list`、PC 側の定義 `input.css:536-554`)。件数は `badge-count` | 全幅の下線タブ。横スワイプで切替え可(`tab-swipe-area`。端 20px・ダイアログ操作中は無視) | `ui/page_skeleton.rs` `SkeletonTabs`、`ui/underline_tabs.rs`、`ui/segmented.rs` |
| 検索入口 | 検索欄・条件タグ・件数行を一覧の直上に置く(帯→注記→検索の順。`ui-design.md:149`) | 本文内の「検索・並べ替え」ボタン 1 つにまとめる。押すと検索ダイアログ(`search_dialog`)。ただし取引明細・銘柄検索はスマホの下部操作帯の検索を例外とする(§3.3・§3.4。`mobile-ui-rules.md:98` の銘柄検索の例外を残し、取引明細を追加する提案。§4 の差分表参照) | `SkeletonSearch` + `ui/search_dialog.rs`、`ui/search_controls.rs` |
| 一覧 | 表(全列表示)。数値列は右・`nowrap`、名称列は最広+2 行まで(`input.css:1092-1127`)。月ごとのグループ行(日ごとのグループは作らない) | `ListRow` の行(器は左右 16px・上下 12px・下に区切り線)。一覧の見出し行は置かない。区切りが必要な一覧(取引明細)だけ月ごとのグループ行(`ListGroupHeader`) | `ui/list_row.rs` `ListRow`・`ListRowButton`・`ListRowLink`・`ListRowStatic`・`ListGroupHeader` |
| 詳細 | PC の詳細パネル(マスター・ディテール。§2)。資産管理・取引明細の 1280 以上で一覧の右に `DetailDialog` と同順の項目を出す(A の取り入れ)。銘柄詳細・ファンド詳細は従来どおり別画面 | 行を押すと保有物は詳細画面へ、出来事はシート(`DetailDialog`)で開く。その場展開はしない | `ui/detail_dialog.rs` `DetailDialog`(項目順は PC 列順と揃える。課題 Codex-4) |
| 下部ナビ | 出さない | ログイン後の全画面で出す。出さない画面(ログイン・404)を列挙する方式 | `ui/site.rs` `BottomNav`、`app.rs` の表示判定 |
| ダイアログ / シート | 中央ダイアログ(`DialogShell` + `search-dialog-*`・`condition-panel`)。条件パネルは「条件を足す」の行のすぐ下に出る小窓。後ろを暗くしない・後ろのスクロールを止めない | 画面下から出る面(`DetailDialog`)・中央ダイアログ・条件はシート。`dialog-panel`(角丸・枠・影・`max-height:88vh`)、題は `dialog-title` | `ui/dialog.rs` `DialogShell`、`ui/detail_dialog.rs`、`ui/confirm_modal.rs` |

## 2. 幅の切り替え規則

| 幅 | 対象 | 決まり |
|---|---|---|
| 390(スマホ) | `width < 64rem` | 1 カラム。要点カード・行リストを縦に積む。下部ナビあり、下部操作帯あり(銘柄検索・取引明細)。表は出さない。帯は開閉式。タブは下線+スワイプ。タップ領域 44px 以上・入力文字 16px 以上 |
| 1280(PC 小) | `64rem <= width < 90rem` | 上ナビ+本文(`content-gutter` 中央寄せ)。資産管理・取引明細は表(全列)+一覧右の詳細パネル(マスター・ディテール)。表の銘柄列・口座列は上限付きで数値列に幅を回す(`input.css:1121-1127` の 1024〜1279 調整)。下部ナビ・下部操作帯なし。表の見出しは `top-14` で固定 |
| 1440(PC 中) | `90rem` 前後 | 1280 と同じ型。`container-page`(90rem)で本文幅を止め、左右に余白を出す。ホームは `home-card-row`(2 列) |
| 1920(PC 大) | `> container-wide`(1680px) | 1440 と同じ型。幅は `container-page` で止める(無限に広げない)。列を増やさない(余白を広げすぎない。`ui-design.md:11`) |

- 切り替え点は `64rem`(=1024px。`lg`)だけ。`max-sm`(390 未満)は CSV の 2 段表示(`csv-kind-row`)に限る。新設のブレークポイントは作らない。
- スマホ先行で作り、PC の詳細パネル、ダークの順に仕上げる(採用方針 `design-decision-p3.md:24`)。

## 3. 画面ごとの配置

配置の順序は §1 の型に従う。画面の目的・タブ・主要操作は `docs/ui-design.md:90-162` が正本で、本書は幅別の配置だけを決める。

### 3.1 ホーム `/`

- PC: 上バー → 集計帯(評価額・評価損益・年間予想配当。`HOME_OVERVIEW_LABEL`「資産の概要」) → `home-card-row`(配当カード+月別棒グラフ / 内訳ドーナツ+凡例に金額と割合) → 評価損益の大きい銘柄 → 最近の配当入金 → フッター。下部ナビなし。
- スマホ: 上バー → 帯(評価額+評価損益。要点カード) → 注記行(価格基準日・取込日) → 配当カード(棒グラフ。期間見出し付き) → 内訳(折りたたみ可。課題 HO-2) → 評価損益上位 → 最近の配当 → 下部ナビ。
- 未ログインは案内カード(`LoginPrompt`)だけ。機能カードは置かない(`ui-design.md:147`)。
- 根拠: `frontend/src/features/home/view.rs`、課題 H-1・HO-1〜HO-4、Codex-2。

### 3.2 資産管理 `/assetbalance`

- PC(1280 以上): 上バー → タブ(すべて/国内株式/投資信託。件数付き) → 帯(評価額合計・評価損益額(率)・前日比・取得総額。タブ固有項目は末尾追加。課題 AS-2) → 注記 → 検索欄 → 条件・件数行(国内株式タブの右端に[構成比を見る ›]) → 一覧表+右の詳細パネル(マスター・ディテール。A の取り入れ。行を選ぶと取得総額・基準価額・配当などを右に出す) → 下部に並べ替え・フッター。
- スマホ: 上バー → タブ(下線+スワイプ) → 帯(開閉式) → 注記 → 「検索・並べ替え」ボタン → 行リスト(`ListRow`。1 段目=銘柄名+評価額、2 段目=口座・数量+損益) → 下部ナビ。行を押すと保有詳細へ(その場展開なし)。
- 保有銘柄詳細・ファンド詳細: [資産管理に戻る]+銘柄名・コード → 現在値と価格基準日 → 数量・取得単価・取得総額 → 評価額・評価損益額(率) → 1株配当・年間配当参考額・取得額基準利回り → [銘柄情報を見る]。`HoldingTiles`(PC 4 列・タブレット 3 列・スマホ 2 列)。
- 構成比 `/assetbalance/composition`: [資産管理に戻る] → 対象・基準の 1 行 → 区分切替(`Segmented`) → ドーナツ+凡例(金額と割合)+順位一覧。PC も同じ型(表にしない)。
- 根拠: `frontend/src/features/asset_balance/view.rs`、課題 AS-1〜AS-3・CO-1・CO-2・X-2。

### 3.3 取引明細 `/receipts`

- PC(1280 以上): 上バー → 種別タブ(配当金/国内株式/投資信託。件数付き)+[CSV管理] → 帯(集計ストリップ。3 項目横並び: 配当金/税額/税引後 または 実現損益/税額/税引後) → 注記行(価格基準日・取込日・絞り込み中) → 検索欄(銘柄名・コード、期間、商品・口座チップ、[条件をクリア])+条件・件数行 → 一覧表+右の詳細パネル(マスター・ディテール。A の取り入れ。行を選ぶと税引前・税額・税引後の内訳を右に出す。項目順は表の列順) → 月ごとのグループ行(件数と小計。「2026年12月 · 3件の合計」の型) → フッター。
- スマホ: 上バー → タブ → 帯 → 注記 → 検索入口(下部操作帯の検索欄。例外。§1.1 参照) → 行リスト(1 行目=日付・銘柄名+主要金額、2 行目=口座+補助。RE-1 の税額目安の追加は Phase 5 で判断。現状は `DetailDialog` 維持) → 行を押すとダイアログ(税引前・税額・税引後) → 下部ナビ。
- 条件パネル: 期間は 5 種類(すべて/年/年月/日/範囲)+入力を下書きで編集し[この期間で絞る]で確定。口座・商品は選ぶとすぐ反映。Esc・外側クリックで閉じる。PC は小窓、スマホはシート。
- 根拠: `frontend/src/features/receipts/view.rs`、課題 RE-1〜RE-4・Codex-4。

### 3.4 銘柄検索 `/search`

- PC: 上バー → 本文(検索欄+ [検索]) → 結果(保有情報 `HoldingTiles` → 現在値・数量・配当の 4 列グリッド → 外部リンク)。下部ナビなし。
- スマホ: 上バー → 本文(結果) → 下部操作帯の検索欄+[検索](例外規定。`mobile-ui-rules.md:98`) → 下部ナビ。
- 空状態の説明は 2 行に縮める(課題 SE-2)。未ログインの保有セクションは案内を出す(課題 SE-1)。
- 根拠: `frontend/src/features/stock_search/`、課題 SE-1・SE-2。

### 3.5 CSV 管理 `/csv`

- PC・スマホ共通: パンくず(資産管理 › CSV 管理) → 取得カード(「すべて取得」。幅固定で文言だけ「取得中...」に変える。ボタン位置不変) → 5 種類の表(種類 | 保存済み | 状態 | ⋯)。行の「⋯」に操作集約(再取得→区切り→削除)。失敗行は左に赤線+薄背景(`csv-kind-row-failed`)、理由は折り返し全文(`csv-detail-reason`)。
- スマホ(390 未満): 種類名の下に状態を出す 2 段表示(`csv-kind-row`)。件数欄・メニュー欄の幅は固定(`csv-kind-col-*`)。横スクロールを作らない。
- 状態は事実だけ(「今日 21:39 に更新」「3日前(10/22 21:10)に更新」「取得できず」「まだ取得していません」)。「最新です」とは書かない。
- 根拠: `frontend/src/ui/csv_page.rs`、`ui-design.md:131-143`、課題 Codex-6・CSV-1・CSV-2。

### 3.6 設定 `/settings`

- PC: 上バー → 左目次(TOC)+右フォームの 2 カラム(表示/データ/セキュリティ/危険な操作)。`settings-toc-link`(読んでいる項目だけ `aria-current`)。
- スマホ: 目次なしの縦積み。セクション先頭に簡易目次(ページ内リンク)を足す(課題 ST-1。`mobile-ui-rules.md` の「残す点」に対する追加。§4 の差分表参照)。
- テーマ・金額単位は `Segmented`、並び順・初期タブは `Select`。ブラウザ/OS 名は短い表示名に正規化し全文は詳細に隠す(課題 ST-2)。
- 根拠: `frontend/src/features/settings.rs`、課題 ST-1〜ST-3・X-6。

### 3.7 管理者 `/admin/logins`

- PC: 上バー → 検索(メール・場所)+[この条件で絞る] → 表(日時 | 結果 | 場所 | ブラウザ・OS | メール)。メール列は省略+`title`/コピー(課題 AD-1)。
- スマホ: 1 件を 3 行分にせず、メール 1 行省略+詳細シート(課題 AD-2 の短縮案を採用。現状維持ではなく改善する)。
- 下部ナビに管理者項目は出さない。設定画面からの導線を検討(課題 AD-4)。a11y spec に admin ルートを追加(課題 AD-3)。
- 根拠: `frontend/src/features/admin/`、課題 AD-1〜AD-4。

### 3.8 ログイン・404

- ログイン: 中央カードのみ。ヘッダーの機能ナビは残るが保護ルート経由で戻るため実害小(課題整理済み)。スマホも同じ型。下部ナビなし。
- 404: 見出し+説明+「ホームに戻る」+関連 3 リンク。下部ナビなし(出さない画面として列挙)。
- 根拠: `frontend/src/features/login.rs`・`not_found.rs`、課題 §2.10。

## 4. `mobile-ui-rules.md` との差分

`mobile-ui-rules.md` はスマホ幅の組み立て方の正本。本書はそれを残した上で、PC 規則と Phase 2 課題の対応分だけを足す。変える点は `mobile-ui-rules.md` への追記提案として扱い、本書では勝手に書き換えない。

| 項目 | 残す点(変えない) | 変える点・足す点(本書の提案) | 理由 |
|---|---|---|---|
| 画面の型・順序 | 上バー→タブ→帯→注記→検索入口→一覧→フッター→下部ナビの順序。使わない段は飛ばす | PC にも同じ順序を適用する(PC とスマホで順序を変えない)。PC の詳細パネルは「一覧」の段の中の右側に置く(段を増やさない) | C の骨格維持。順序の二重基準を作らない |
| 上バー・下部ナビ | スマホの紺帯・件数は `title_count`・下部ナビは全画面・出さない画面の列挙方式 | PC はロゴ+グローバルナビ+アカウント、下部ナビ・下部操作帯なし(PC の検索欄は本文内)。スマホは取引明細・銘柄検索だけ下部操作帯の検索を例外とする(`mobile-ui-rules.md:98` の銘柄検索の例外を残し、取引明細を追加する提案) | C の上ナビ維持。縦ナビは採用しない |
| タブ | 全幅の下線タブ+スワイプ(`tab-swipe-area`) | PC は枠つきピル型(`page-tab-list` の PC 定義)。件数は `badge-count`。スワイプはスマホだけ | 現行の PC ピル型を維持 |
| 帯 | 全幅・角丸なし・開閉は帯全体 | PC は角丸+グラデーションの 1 行(`summary-band` の PC 定義)。項目順は全タブで固定しタブ固有項目は末尾追加(課題 AS-2) | 定点観測しやすくする |
| 一覧 | `ListRow`・見出し行なし・月ごとのグループ行のみ | PC は表(全列表示)+右の詳細パネル(マスター・ディテール)。銘柄列最広+2 行表示(課題 AS-1)、数値列 `nowrap`、見出し `top-14` 固定 | A の PC 詳細パネルの取り入れ |
| 詳細 | 保有物は詳細画面へ・出来事はダイアログ・その場展開なし | 項目順を PC 列順に揃える(課題 Codex-4)。スマホの税額目安の追加(RE-1)は Phase 5 判断で現状維持 | 一覧と詳細の対応を明確にする |
| 空・失敗 | `EmptyState`・`ListSkeleton`・`ListLoadError`(裏の再取得失敗だけ `Alert`) | 空の説明は 1〜2 行に揃える(課題 X-3)。空状態では条件行を出さない(課題 RE-4) | 画面間のばらつきをなくす |
| 構成比への入口 | 件数行の右の 1 か所だけ(スマホ) | PC 上バーの重複ボタンはやめる(件数行に寄せる。課題 X-2・CO-2) | 入口の重複をなくす |
| 設定・管理者 | TOC は PC だけ(`hidden lg:block`) | スマホの設定に簡易目次(ページ内リンク)を足す(課題 ST-1・X-6)。管理者に設定からの導線検討(AD-4)+ a11y 追加(AD-3)。メール省略+コピー(AD-1)、UA 正規化(ST-2) | 長い画面の到達性 |
| グラフ | `home-chart-*` の棒グラフ(月次)+ドーナツ(構成) | 曲線グラフ禁止(月次は棒だけ)。円グラフは A 方式(凡例に金額と割合)を維持。達成系=単色・内訳系=系列色と決めて凡例に書く(課題 HO-3) | 採用方針のグラフ規則 |
