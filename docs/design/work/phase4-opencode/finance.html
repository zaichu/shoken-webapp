Phase 4 見本:金融データの表示規則(架空データ)

架空データ(9900 番台・規則的な値)。合計は一致させている。基礎トークンは tokens.css(正本 frontend/style/input.css の抜粋)。良い例・悪い例の対で示す。

1. 数値:桁区切り・右そろえ・等幅 / 小数桁 / 全桁表示

finance-data.md §1。Amount + format_currency。¥28.6M のような省略は使わない。

良い例
銘柄評価額評価損益
9901 架空電機¥1,234,500+¥234,500
9902 架空食品¥876,500-¥23,500

右そろえ・等幅で 1 の位がそろう。1株配当は列内で桁そろえ:¥72.5 / ¥71.0 / ¥0.0。

悪い例
銘柄評価額評価損益
9901 架空電機¥1234500¥1.23M
9902 架空食品¥876500▲23500

区切りなし・左そろえ・短縮・▲。桁を読み違える。

2. 増減:符号+色 / ゼロと欠測 —

finance-data.md §2。Delta=符号+色、Plain(残高・価格・予想)=通常色。▲▼禁止。

良い例
評価損益 +¥234,500 / -¥23,500 / ¥0
税額 -¥16,346(支払) / 還付 +¥1,200
評価額 ¥1,234,500(通常色・+なし) / 年間予想 ¥196,373(通常色)
2月配当 ¥0(ゼロ) / 基準価額 —(欠測)
悪い例
評価損益 ¥234,500(色のみ。印刷で正負不明)
評価額 +¥1,234,500(残高に +。損益と紛らわしい)
税額 ¥16,346(通常色。払ったお金に見えない)
基準価額 ¥0(ゼロ円に見える。欠測は —)

3. データ時点:取込日と価格基準日を別ラベル・年付き

finance-data.md §3。price_as_of + home_import_label。10/20 のような年なし表記は使わない。

良い例
価格基準日 2026/10/20 ・ データ:2026/10/21 取り込み
月別配当(2026/01 〜 2026/12)
悪い例
10/20 時点(何の時点か・何年か分からない)
データ:10/21 取り込み(価格基準日と混ざる)

4. 合計と内訳の一致 / 紺帯の決まり

finance-data.md §4。評価額 ¥3,345,000 = 内訳の和。帯の中も符号+色(明色)。

評価額
¥3,345,000
評価損益
+¥345,000
取得総額
¥3,000,000
2026年12月 · 3件の合計 +¥74,000 -¥15,020 +¥58,980

悪い例:年間合計 ¥3,163,438 に対して月別合計 ¥3,099,249、小計「3件」に行 2 行(不一致は不具合)。

5. グラフ:月次=棒 / 構成=円+凡例(金額と割合)

finance-data.md §5。曲線禁止。凡例は色+名前+金額+割合。前年は比較色。

良い例(棒+凡例)
月別配当(2026/01 〜 2026/12)・合計 ¥300,000(単一の系列)
123456789101112
月別配当(配当金の受取額) 合計 ¥300,000

単一の系列のため棒は1色(`chart-3`)。資産構成の系列色(`chart-1`/`chart-2`)は使わない。

資産構成(評価額基準)・合計 ¥3,345,000
国内株式 ¥2,111,000 63.1%
投資信託 ¥1,234,000 36.9%

構成は円グラフ+凡例(金額と割合)。円の色・順序と凡例を一致させる。

悪い例
月別配当(期間なし・合計なし)
12か月を滑らかな曲線で結ぶ(月と月の間に値があるように誤読)
国内株式 63%　架空グロー…(金額なし・省略で識別不能)

6. ステータス表示 / 欠測・長い名前

finance-data.md §6・§7。状態名と時点を別項目に。色だけにしない。「最新です」と書かない。

良い例
状態:今日 21:39 に更新
状態:取得できず [詳細](理由全文を折り返し表示)
評価額 ¥3,345,000(一部更新待ち)
架空グローバル先端素材ソリューションファンド(2行まで表示。全文は行詳細で)
悪い例
要更新・15日前(10/31 09:12)に更新(意味が読み取れない)
最新です(楽天証券側の新規有無は分からない)
架空グローバル先端素材ソリュ…(全文の到達手段なし)
