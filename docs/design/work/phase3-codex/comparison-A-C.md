# コンセプト A / C 比較

| 観点 | A：金融プロフェッショナル向け高密度 | C：情報密度と視認性の両立 |
|---|---|---|
| 骨格 | PC は細い左縦ナビ。ホームは上段集計・中段チャート/配分・下段2表の複数ペイン。資産は一覧＋右詳細のマスター・ディテール。 | 既存の上ナビを維持。要点カードから関連グラフ・内訳へ続き、下段に展開式一覧を置く「要点 → 詳細」。 |
| 密度 | 表の基本行高28px、見出し固定・固定列幅・等幅数値。PCホームでは要約4値に加え、配当12か月、口座別3区分、損益上位3件、入金3件を同時表示。 | 表の基本行高44px、余白を広めに取る。PCホームは大きな要点カード3枚、配当推移・資産配分、損益上位3件・最近の入金3件を表示。行の詳細は展開時に表示。 |
| ナビ | PC は左レールのアイコン＋ラベル。スマホは簡潔なページ見出しと上部のプレビュー切替。 | PC はロゴ・グローバルリンク・アカウントの上ナビ。スマホも上ナビを短縮して維持。 |
| 操作性 | 表の選択で右詳細の対象が切り替わる。多くの銘柄を連続比較しやすい。スマホでは要約リストになり、詳細は画面を切り替える想定。 | 行を開閉して必要な詳細を見る。スマホは要点カードとアコーディオンで段階的に確認。検索・並べ替え・期間/口座/商品条件を一覧直前に置く。 |
| 視認性 | 列・罫線・数字位置を手掛かりに比較する。情報量を優先するため、行の読み取り密度は高い。スマホ明細にも税引前・税額・税引後を2段で残す。 | 大きい数値、カードの余白、展開領域で階層を作る。最初の一覧は簡潔で読みやすいが、複数行の補助項目を比べるには開閉操作が増える。 |
| 実装コスト | 左レール、PC 固定列表、選択行と詳細ペイン、スマホ用要約表示を実装する。選択状態と画面幅ごとの一覧構造が必要。 | 共通上ナビ、要点カード、レスポンシブな展開行/アコーディオンを実装する。開閉状態とアクセシブルな展開操作が必要。 |

## 共通の表示型

両案とも評価額・損益・配当・税額・数量・率・日付に同じ書式を使う。金額は円記号と桁区切り、損益/配当は符号付き、税額は負号付き。配当受取を増加色、税額を減少色で区別する。時点は価格基準日と CSV 取込日のラベルを付けて表示する。画面用語と書式の実装時の正本は `docs/ui-design.md`、`frontend/src/ui/labels.rs`、`frontend/src/ui/format.rs`。
