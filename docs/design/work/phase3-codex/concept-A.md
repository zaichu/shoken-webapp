# コンセプト A：金融プロフェッショナル向けの高密度 UI

## 理念

複数の保有資産や入金履歴を短時間で照合する利用者に向け、一覧で比較できる項目を増やしながら、ラベル・列・罫線で意味の境界を明確にする。ホームから資産管理、取引明細まで紺のヘッダーと橙の現在位置を維持し、数値の右揃え、符号、色、データ時点は現行の共通ルールに従う。根拠は Phase 1 の画面で PC の一覧は比較しやすい一方、明細の列数が多く目的の数値へ視線を運びにくいこと、スマホでは補助額が詳細操作の後に現れること（Phase 2 Codex 課題4、OpenCode RE-1）。

## ビジュアル

- 色: ヘッダー/集計帯 `#0F2A4A`、深い紺 `#0B1F38`、現在位置 `#F2B33D`、ページ `#F3F5F8`、面 `#FFFFFF`、本文 `#0F172A`、補助 `#4B5563`、罫線 `#D1D5DB`。増減は共通値の緑 `#0B7A4B` / 赤 `#C0362C`。ライト/ダークとも意味の割当を変えない。
- 文字: Noto Sans JP。本文 13–14px、表 12px、ラベル 11px、見出し 20–24px、主数値 24px。金額・率・数量は等幅数字を優先し、全て右揃え。
- 余白: PC 本文最大幅 1440px、左右 24px、段間 12px、表行高 36px。スマホ左右 16px、行高 56px、行内は名前/金額と補助情報の2段。
- 角丸/影: 集計帯 6px、入力 6px、タブ 16px、面は 6px。カードの影を避け、1px罫線と背景差で区切る。
- アイコン: 既存の線画アイコンを 16–20px、操作ラベルと併記。状態や損益をアイコン/色だけで示さない。

## 情報設計

- ナビゲーション: PC は紺の上部ナビ、スマホは既存の下部ナビ。ホーム/資産管理/取引明細/銘柄検索を維持し、アカウント操作は右上。
- 集計帯: 評価額・評価損益・前日比・取得総額を PC 4列、スマホ2列×2段。ホームでは配当実績と予想を別枠にし、「価格基準日」「CSV 取込日」を完全日付で表示。
- 一覧: PC は固定列幅の表、銘柄名に広い列を確保し、数値列は右揃え。資産管理の全件を同一型にする。取引明細は月グループと小計を残す。
- 詳細: 行選択で既存の詳細画面/シートへ遷移。配当明細は税引前・税額・税引後の順を一覧と詳細で揃える。

## 操作性・視認性

検索・並べ替え・条件入口と件数は共通位置に置き、スマホでは「検索・並べ替え」1入口にまとめる。全機能、タブ、状態を保ち、長い名称は PC で2行まで表示、スマホは折返しとする。フォーカスは2px以上の明瞭な輪郭、操作領域は44px以上。本文色と面の組み合わせはコントラスト4.5:1以上を目標にし、実測は実装時に確認する。数値は右揃えで桁を揃え、単位・符号・増減色を全画面で共通化する。

## 適する利用者・場面

複数銘柄を横断比較する利用者、保有一覧や月ごとの配当額を日常的に照合する場面に適する。PC での一覧閲覧を特に重視する。

## 実装コスト

中〜高。主な影響箇所は `frontend/style/input.css`（表の列幅、密度用の余白・行高、ダーク時の罫線）、`frontend/src/ui/page_skeleton.rs`（共通段間）、`frontend/src/ui/list_row.rs`（スマホ2段の行）、`frontend/src/features/asset_balance/view/all_list.rs` と `asset_table.rs`/`fund_table.rs`（名称列と固定列）、`frontend/src/features/receipts/view/table.rs`/`cards.rs`（税額表示と数値列）、`frontend/src/ui/amount.rs`（表示型は維持）を見込む。トークンと既存部品の調整が中心だが、PC 表の可読性を保ったまま詰める調整が必要。

## 長期の拡張性

テーブル列を用途別に選べる規則、長い名前の段階表示、集計帯の共通順序を維持すれば画面追加に追従しやすい。画面固有の色・数値書式・行部品を増やすと一貫性を損なうため、既存トークンと共通部品の拡張に限定する。

## Phase 2 課題への対応

- Codex 1 / OpenCode X-4: 時点種別を分け、価格基準日・取込日を年を含む書式で表示する。
- Codex 2: ホームの要約を共通帯に寄せ、配当実績・予想・構成比を明確に分離する。
- Codex 3 / OpenCode AS-1: 名称列を広げ、2行表示と詳細導線で全文識別を可能にする。
- Codex 4 / OpenCode RE-1: 一覧の主値を明示し、補助金額を共通順で見せる。スマホは追加行で税引前・税額を比較可能にする。
- Codex 5: 凡例とランキングの順序・名称・割合を揃え、色以外の対応情報を維持する。
- Codex 6 / OpenCode CSV-1: 状態と取得時点を別項目にする。
- Codex 7 / OpenCode ST-2: 生の User-Agent は一覧に出さず、ブラウザ/OS の短い表示へ整理する。
- Codex 8 / OpenCode RE-4: 空状態では意味のない条件追加を隠し、共通の空状態と再試行位置を保つ。
- OpenCode ST-1 / X-6: 設定の長い画面にモバイルでも使える目次を置く。
- OpenCode AD-1/AD-2: メールは省略表示とし、詳細で全文を確認できる型にする。
- OpenCode X-1 (H-2): 原寸で「再読み込み」と確認済みのため変更しない（統合担当判定により取り下げ）。
