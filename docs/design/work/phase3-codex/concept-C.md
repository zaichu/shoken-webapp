# コンセプト C：情報密度と視認性を両立した UI

## 理念

金融情報の比較に必要な密度は保ちつつ、画面の主従と余白を調整し、慣れていない利用者にも数値の意味と次の操作を追いやすくする。現在の「証券Web」ブランド、紺のヘッダー、橙のアクセントを継承し、集計帯・検索入口・一覧行を画面間で共通化する。根拠は Phase 1 のホームが PC では広い2カラム、スマホでは配当グラフと資産内訳が縦に続き主要情報を行き来すること（Phase 2 Codex 課題2）、資産一覧では長い名称、明細では税額の見つけにくさが指摘されたこと（Codex 課題3/4、OpenCode AS-1/RE-1）。

## ビジュアル

- 色: ヘッダー/集計帯 `#0F2A4A`、現在位置 `#F2B33D`、ページ `#F3F5F8`、面 `#FFFFFF`、本文 `#0F172A`、補助 `#4B5563`、罫線 `#D1D5DB`、正負 `#0B7A4B` / `#C0362C`。ダークでも同じ意味を維持し、背景と文字の明度を反転する。
- 文字: Noto Sans JP。本文 14px、補助 12px、見出し 20px、集計の主数値 26px。金融数値は右揃え、等幅数字を使用。
- 余白: PC 本文最大幅 1440px、左右 32px、段間 16px、表行高 44px。スマホ左右 16px、行の上下 12px、タップ領域44px以上。
- 角丸/影: 集計帯は角丸6pxでページ幅に沿わせる。入力と面は8px、タブは全幅下線型。面に薄い1px罫線、影は重なりを示すダイアログだけに使用。
- アイコン: 線画16–20px、文字ラベル併記。状態を色だけに依存させない。

## 情報設計

- ナビゲーション: PC 上部ナビ、スマホ下部ナビ。現行4主要項目とアカウント導線を保持。
- 集計帯: 主数値1つと補助値を同じ帯に配置。ホームは評価額・評価損益を主役にし、配当実績/予想を別カードで混同させない。資産管理と取引明細は現行の集計項目を保持し、順番を固定。
- 一覧: PC 表は数値列を右揃えにし、名称に余裕を配分。スマホは共通の2段行、名前と主金額を1段目、日付/コード/口座と補助金額を2段目。月グループと小計は残す。
- 詳細: 行から既存詳細画面またはシートへ移動。税引前・税額・税引後の順と符号/色は一覧・詳細で共通。

## 操作性・視認性

検索入口・条件タグ・絞り込み件数の順番を統一し、スマホの検索は1つの入口から操作する。補助数値は行を開かなくても把握できる画面とし、密度が上がり過ぎる場合は2段目へ移す。長い名前は完全表示を優先し、一覧の高さは不揃いを許容する。キーボードフォーカスは2px以上の輪郭で表示し、コントラスト4.5:1以上を確認する。数値は単位・符号・正負色を共通ルールに従わせ、基準日・取込日はラベルと完全日付を併記する。

## 適する利用者・場面

スマホで資産概要を確認する利用者、日々の配当や評価額を確認しつつ詳細比較も行う場面に適する。PC とスマホの情報差を抑えながら読みやすさを保つ。

## 実装コスト

中。`frontend/style/input.css`（余白・タイプスケール・明暗トークン）、`frontend/src/ui/page_skeleton.rs`（段順）、`frontend/src/ui/summary.rs`（主従の一貫性）、`frontend/src/ui/list_row.rs`（補助値・長い名称の2段表示）、`frontend/src/features/home/view.rs`（共通帯とカード順）、`frontend/src/features/receipts/view/cards.rs`/`table.rs`（税額情報）、`frontend/src/features/asset_balance/view/all_list.rs`（名称と金額の配置）が主な変更候補。既存の共通部品を中心に調整し、ページごとの個別レイアウト追加を避ける。

## 長期の拡張性

共通骨格を維持したままカード内の要約・補助段を構成でき、新しい資産種別や明細種別を同じ型に追加しやすい。項目順、数値書式、日付の意味を共通化し、情報量の増加はラベル階層と詳細表示で吸収する。

## Phase 2 課題への対応

- Codex 1 / OpenCode X-4: 価格基準日と CSV 取込日の意味を分け、完全日付に統一する。
- Codex 2: ホームの集計を共通帯へ寄せ、配当・内訳は要約後に並べる。
- Codex 3 / OpenCode AS-1: 長い商品名を複数行で保持し、名称の識別性を上げる。
- Codex 4 / OpenCode RE-1: 税引後を主値、税引前・税額を補助段に出し、PC/スマホの確認手数を近づける。
- Codex 5: 凡例と一覧を同順にし、名称と割合を色以外でも対応させる。
- Codex 6 / OpenCode CSV-1: 状態ラベルと最終取得日を分ける。
- Codex 7 / OpenCode ST-2: User-Agent 生文字列を短いブラウザ/OS 表示に置換する。
- Codex 8 / OpenCode RE-4: 空状態では条件行を出さず、次の行動を示す。
- OpenCode ST-1 / X-6: モバイル設定にセクション目次を追加する。
- OpenCode AD-1/AD-2: 長いメールの省略と詳細確認の導線を揃える。
- OpenCode X-1 (H-2): 「再読み込み」の誤字指摘は取り下げ済みのため変更しない。
