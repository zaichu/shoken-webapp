# Phase 3 の評価と推奨方針(統合担当・Claude、2026-11-15)

見た画像: A=concept-a-asset-pc / home-mobile、C=concept-c-home-pc-light / home-mobile、B=B-home-pc / B-asset-sp / B-receipts-pc。

## 比較
| 観点 | A 高密度(左縦ナビ+マスター・ディテール) | B シンプル(1カラム・大きな数字) | C 両立(上ナビ維持+要点カード) |
|---|---|---|---|
| ビジュアル | 落ち着いた紺。等幅の数字が映える。スマホは 11px の文字があり小さい | 余白広く最も読みやすい。数字が大きい | 要点カードの大きな数字が明快 |
| 情報設計 | PC で一覧と詳細を同時に見られる(資産管理)。ホームは棒グラフ+円グラフで離散データの扱いが正しい | 情報を段階表示にして絞る。円グラフを横バーに替え、口座別・月別は折りたたみ(情報の入口が1つ深くなる) | 現行の骨格を維持。要点→詳細の順が自然。ただし月次配当を滑らかな曲線で描いており誤解を生む |
| 操作性 | PC に最適。スマホはタップ領域が小さくなりがち | スマホに最適(下部ナビ・大きなタップ領域) | PC・スマホとも無理がない |
| 視認性 | 高密度のため、慣れが要る | 最高 | 高 |
| 利用者との適合 | 個人の資産管理。PC で一覧を見比べたいときに強い | 利用者は主にスマホで使う(実際の確認も全部スマホ)ため適合が高い | 両方の利用に無理なく適合 |
| 実装コスト | 高(ナビを縦に、表の密度、詳細パネルの新設。CSS トークン・ページ骨格・ナビ部品を全面的に変更) | 中(カード・余白・文字サイズ中心。構成の変更は小さい) | 低〜中(集計帯をカードに、既存の骨格・部品を維持) |
| 拡張性 | 画面が増えても同じ型で足せる。縦ナビは項目が増えても耐える | 段階表示で情報が増えても破綻しにくい | 現行の型の延長。大きな変更なしに育てられる |

## 推奨(採用方針)
**C を骨格の基準にし、B のスマホの作りと A の PC 詳細パネルを取り入れるハイブリッド**。
- 骨格・ナビ・集計: C(上ナビ+要点カード。現行から連続し、実装コストが低い)
- スマホ: B(1カラム、大きな数字、下部ナビ、タップ領域 44px 以上、余白広め)。利用者の主な使い方がスマホのため、ここを最優先で磨く
- PC(1280 以上)の資産管理・取引明細: A の『一覧+右の詳細パネル』(マスター・ディテール)を追加。縦ナビは採用しない(実装コストと現行からの距離が大きい)
- グラフ: 月次の金額は棒グラフ(離散値)。滑らかな曲線は使わない(C の欠点)。円グラフは A 方式(凡例に金額と割合)。B の『横バーに統一』は口座別の入口を深くするため採用しない
- 数値: ¥ と桁区切りの全桁表示(¥28.6M のような省略は使わない)。増減は符号+色+(必要なら)文字。データ時点は『取込日』と『価格基準日』を別ラベルで、どちらも年を含む
- 見送る: A の縦ナビ、B の円グラフ廃止(横バー化)、C の曲線グラフ
- 実装の進め方: スマホ先行 → PC の詳細パネル → ダーク調整(implementation-plan.md に段階を書く)

## 守らせる品質基準(Phase 4・5)
- 合計と内訳の一致(評価額と内訳、配当の年合計と月別合計、件数と一覧)。モックでも合わないものは不具合として扱う
- 既存の機能・画面・状態を落とさない(phase1-codex/screen-inventory.md の全項目)
