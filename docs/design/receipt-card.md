# 取引明細スマホカードの方針と案 (Issue #2079)

対象: 取引明細の国内株式・投資信託・配当金タブのスマホ行 (390幅の2行リスト)。
PC の表・集計帯・月見出しは変えない。

## 行の役割の規則

実在の証券・家計アプリの取引履歴・実現損益・配当一覧の作りを参考にした。
(web 検索が使えない環境で書いたため、出どころ URL は未付与。レビュー時に実機で確認して追記する。
確認先の目安: 楽天証券 iSPEED「取引履歴」、SBI 証券アプリ「取引履歴・実現損益」、
マネーフォワード ME「入出金・資産内訳」、Robinhood「History」。いずれもアプリ内の履歴画面)

1. 主役の金額は1つだけ。行の右上は「いま残る・動いた金額」1つ (税引後・受取額) にする。
   正負の色は `Amount` の Delta の決まり (正=緑・負=赤・0=無色) のまま。
2. 補足の金額は最大1か所。メタ行 (日付・コード・口座) か金額下の小字のどちらか。
   2か所に金額を出すと主役が割れる (今回の「税引前はいらないかも」の原因)。
3. 税引前・税額は詳細に回してよい。条件は「行を押すと開く詳細ダイアログに
   税引前・税額・税引後が全部あること」。現状の `DetailDialog` (右列) は満たす。
4. 配当金タブにそろえる。配当金は既に金額1行 (税引後=受取額) で迷いがない。
   株式・投信も同じ形にするとタブ間の学習コストが下がる。
5. 新しい色・文言は足さない。色は今のトークン、文言は `ui::labels` のみ。
6. 端データで確かめる。長い銘柄名は折り返し・省略なし (e2e の決まり)、
   同じ日の同じ銘柄が複数あっても月見出しに集約、損失は符号と赤の両方で示す
   (色だけに頼らない)、0円は符号なし・無色。

## 元々のデザイン

- 税引前の小字は `02001a0c` (ui: 資産管理と取引明細のスマホ検索・並べ替えを仕上げる
  #1970 #1971、#1980、2026-11-17) で入った。その直前までは主役の税引後のみ。
  さらにその1つ前は主役の下に税引後の小字 (主役と重複) だったため、
  `02001a0c` で小字を税引前に直した経緯がある。
- 比べる基準は `02001a0c` の親 `46dac83e`。カードの形自体の直近変更は
  `a9c6fd3c` (ui: Issue #1961 表とカードを仕上げる、#1967) のまま。

## 案 (撮影用の切り替え。既定=現状)

詳細ダイアログ (税引前・税額・税引後の3行) は3案とも変えない。
行から消す項目はすべて詳細で見られる。

- 案A「金額1行」: 税引前の小字を出さない。国内株式・投資信託も配当金と同じ
  金額1行にそろえる。`46dac83e` の形に戻る。
- 案B「メタに税引前」: 金額は税引後1行。2行目のメタ末尾に
  「· 税引前 ±¥X」を小字で添える。情報は残しつつ主役は1つにする。
- 案C「低く詰める」: 案A + 行の上下パディングを py-2→py-1、行内の段間を
  gap-0.5→0 に詰めた低いカード。スマホでも効く値にし、
  中身2行でタップ領域 44px 以上を保つ。

切り替えは `frontend/src/ui/receipts.rs` の `RECEIPT_CARD_PROPOSAL`
(0=現状、1=A、2=B、3=C)。本実装では選ばれた案だけ残し、
この定数と使われなかった枝は持ち込まない。
