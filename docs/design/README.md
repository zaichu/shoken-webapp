# 設計資料の読み方

この目次は、担当Aの全体設計資料を案内する。確認対象はリポジトリのコード・SQL・ワークフローであり、本番サービスへ接続して確認した記録ではない。
Mermaid は、文章中の記法から図を表示する仕組み。GitHub のプレビューで各図を読める。

## 図と根拠の読み方

各図の直前に「この図で分かること」、直後に根拠の `path:行` を置く。行番号は本資料を作成した時点のものなので、変更後は関数名・テーブル名も手掛かりにする。
実線・破線の意味は図ごとに説明する。ER図の線はDBが保証する関係だけを表し、名前が似た列を推測で結ばない。
確認できなかった実環境の状態は各資料の「未確認」に、既存文書との差は「文書との食い違い」に書く。
用語が3つ以上並ぶときは表(用語|意味)にする。
