# 証券Web 画面設計(スマホ優先)

見た目より操作性を優先する。全ページ同じ型を使い、部品は最小数にする。

## UI の要件(必須)

- 主要操作は2タップ以内。頻繁に使う操作は常時表示
- サイドパネル(ドロワー)は使わない。スマホでは別ページにする。モーダルは破壊的操作の確認だけ
- 主要ナビは文字付きの下部ナビ(ホーム/資産管理/取引明細/銘柄検索)
- 各画面の目的は1つ
- 横スクロール禁止。PC の横広デザインをスマホに持ち込まない。PC でも余白を広げすぎない
- 一覧は 390×844 の初期表示で4件以上読める密度にする。重要情報をカード化しすぎない(区切り線の行で並べる)
- 同じ情報を複数箇所に出さない
- アイコンだけのボタン禁止(文字ラベル)。hover 前提の UI 禁止。ドロップダウンに主要機能を隠さない
- フォームは1画面で完結。破壊的操作以外で確認ダイアログを出さない
- 色は意味のあるもの(損益の正負・選択状態・警告/危険)だけ
- スマホの主要操作は親指が届く画面下部に置く。タップ領域は 44px 以上、入力の文字は 16px 以上

## 用語と書式(全画面の共通ルール)

画面に出す用語・書式は1か所に定義し、全画面がそれを使う。画面ごとに同じ意味の文言や
書式関数を書かない(|Issue #1467|)。

### 用語は `frontend/src/ui/labels.rs`

- 評価額・評価損益・前日比・取得総額・年間配当・取得額利回り・1株配当・口座・分配金コース・
  税額・税引後・数量・実現損益など、画面のラベルは `labels.rs` の定数(`&'static str`)で定義する
- 文言が画面ごとに違うときは「対象名を引数にした関数」にする
  (`search_placeholder(対象名)` / `pick_title(対象名)` / `count(件数)` / `group_count(見出し, 件数)`)
- 欠測表示は `MISSING`("—")、更新待ちの表示は `PENDING_UPDATE`("更新待ち")を使う
- **新しい文言は用語集に足してから使う**。画面側に直接書かない

### 書式は `frontend/src/ui/format.rs`

- 金額(円マーク・桁区切り・符号)は `format_currency` / `format_row_valuation_amount`、
  率は `format_fixed_percent` / `format_percentage_value`、数量は `format_number_value` を使う
- 1株・1口あたりの金額(取得単価・現在値・基準価額・1株配当)は `format_unit_price` を使い、
  列の中の桁は `unit_price_decimals` でそろえる(整数円の値しかない列は0桁)
- 日付は `format_price_date`(基準日 "MM/DD") / `format_iso_date`("YYYY/MM/DD") /
  `format_short_date`("M/D") を使い、基準日の注記は `labels::price_as_of`("10/21 時点")にする
- 同じ意味の書式関数を作らない。作りたくなったら `format.rs` に足す

### 検査

- `labels.rs` の単体テストが、統一前の語(「含み損益」「評価額(投資信託)」「絞り込み」ほか)が
  `frontend/src` の他のソースに現れないことを確かめる。新しい画面作るときは通ること
- 検査は文言の完全一致ではなく、**定義の重複**を禁じるもの

## 共通の型

```text
ページ名                       [低頻度操作への文字リンク]
種別切り替え(必要なページだけ)
圧縮した集計(数値を扱うページだけ)
主内容(一覧/詳細/フォーム)
──────── 画面下部に常設 ────────
操作帯(検索欄・適用・保存など)
ホーム|資産管理|取引明細|銘柄検索
```

共有部品は3つだけ: 共通ページ枠(見出し・戻る・本文・下部操作帯・下部ナビ)/一覧操作帯(検索入力・消去・条件の入口と解除)/圧縮集計欄。

## ページの骨格(資産管理・取引明細)

資産管理と取引明細は次の順番で、同じ部品を使う。順番は変えない。

```text
見出し(ページ名 + 件数) → タブ → 帯 → 注記 → 検索欄 → 条件 → 表
```

- 部品は `frontend/src/ui/page_skeleton.rs` に置く(見出し行・タブ行・帯の枠・注記行・検索と条件の行)
- 余白は `frontend/style/input.css` の `--space-*` トークン1セットだけで決める
  (`--space-tabs` / `--space-summary` / `--space-note` / `--space-search` / `--space-condition` / `--space-table`)
- 帯の枠は `.summary-band`(資産管理・取引明細・ホームで同じもの)、タブは `.page-tab`(資産管理・取引明細で同じもの)
- 注記の行は検索で絞り込んでいるときだけ「絞り込み中(N件 / M件)」を出す(条件が無いときは出さない)
- 検索欄の件数(「N件 / M件」)は条件の行の右端に置く
- 取引明細の月ごとのグループ行は日付で区切る表のため残す
- スマホは取引明細の検索欄を下部操作帯に置く(共通ページ枠の運用)。資産管理は本文の中に置く

## 共通部品の規則

- **空状態・案内のカード**(`ui/empty_state.rs` の `EmptyState`): 縁は実線。アイコン→見出し→説明→操作の順に並べる。
  ログイン案内(`ui/login_prompt.rs` の `LoginPrompt`)、銘柄検索の空状態、ホーム(ログアウト中)は同じ部品を使う
- **検索欄**(`ui/search_controls.rs` の `SearchBox` + `SearchTextInput`): 高さ・角丸・虫眼鏡アイコン・余白は全画面共通。
  違いは実行ボタン(`SearchSubmitButton`)があるかだけ。文言は `labels::search_placeholder(対象名)`の「〇〇で検索」の型
- **ボタン**(`ui/button.rs`): 3種類だけ。主(`Primary`=塗り・強調色)・副(`Secondary`=枠線)・無効(`disabled`=薄い・押せない)。
  検索の実行ボタンは入力が空のあいだ無効、入力すると主の色

## 1. 資産管理トップ `/assetbalance`

- 目的: 保有資産の集計と銘柄一覧を素早く確認する
- 保有種別(すべて/国内株式/投資信託)をタブで切り替える。各タブは帯・注記・検索欄・一覧を同じ作りで出す(用語・検索欄の文言・注記と計算基準の位置をそろえる)
- レイアウト(上から): ページ名と件数と[CSV管理] → 保有種別のタブ → 圧縮集計(評価額合計・評価損益額(率)・年間配当参考額・取得額基準利回り、2列×2行)→[取得額の構成比を見る] → 注記(基準日・前日比の件数・計算基準)→ 検索欄 → 条件 → 保有一覧 → 下部に並べ替え・ナビ
- 一覧の1行: 銘柄名・コード / 評価額 / 評価損益額(率、正負は符号と色)。配当・利回りで並べているときはその値も行に出す。行を押すと保有銘柄詳細へ
- 主要アクション: 文字で絞り込み、並べ替え、保有銘柄詳細へ
- 優先順位: 一覧 > 集計 > 並べ替え > 構成比への入口

## 2. 構成比詳細 `/assetbalance/composition`

- 目的: 取得額がどの銘柄に集中しているかを確認する
- レイアウト: [資産管理に戻る] → 対象(保存済みの保有全体)・基準(取得総額)の1行 → 比率の大きい順の一覧(銘柄名・取得額・% と単色の棒)
- 主要アクション: 保有銘柄詳細へ、戻る
- 合計0なら「算出不可」。時価構成比とは呼ばない

## 3. 保有銘柄詳細 `/assetbalance/holdings/:id`

- 目的: 1銘柄の数量・価格・損益・配当を確認する
- レイアウト: [資産管理に戻る] 銘柄名・コード → 現在値と価格基準日 → 数量・取得単価・取得総額 → 評価額・評価損益額(率) → 1株配当・年間配当参考額・取得額基準利回り(取得状態も)→ [銘柄情報を見る](/search?code=…)
- 保存データの ID で特定し、URL を直接開いても表示できる

## 4. 取引明細トップ `/receipts?kind=dividend|stock|fund`

- 目的: 選んだ種別の明細と、その検索結果の集計を確認する
- レイアウト: ページ名と件数と[CSV管理] → 種別タブ(配当金/国内株式/投資信託)→ 圧縮集計(件数と金額を1か所に。配当=配当金・税額・税引後、株式・投信=実現損益・税額・税引後)→ 注記 → 検索欄 → 条件 → 明細一覧。スマホは検索欄を画面下部の操作帯に置く
- 検索欄は1つの面にまとめる: 今の条件のタグ(「期間: 2026年9月 ×」。× で個別解除)・銘柄名/コードの入力。件数は条件の行の右端(「4件 / 77件」)・[すべてクリア]も条件の行の右端
- 検索欄の下に「条件を足す: [＋期間][＋口座][＋商品]」を常に表示する。押すと小窓(PC)/下から出るシート(スマホ)で選び、確定するとタグとして検索欄に入る。Esc・外側のクリックで閉じる
- 期間はすべて/年/年月/日/範囲の5種類と、それぞれの入力(年・月・日・開始日〜終了日)を持つ。口座・商品は選ぶとすぐタグになる(もう一度選ぶと外れる)
- 一覧の1行: 日付・銘柄名(コード)・口座・主要金額(配当=税引後受取額、株式・投信=税引後損益)。残りは行内の[詳細]で開く
- 文字検索は部分一致で、期間・商品・口座の条件と併用できる。集計は検索結果と同じ対象
- 優先順位: 一覧 > 集計 > 検索

## 5. 検索条件の小窓・シート `/receipts` の「条件を足す」

- 目的: 明細の条件を1つずつ足す・外す。条件だけの別ページは持たない
- 期間の小窓: 種別(すべて/年/年月/日/範囲)と入力を下書きで編集し、[この期間で絞る]で確定する。Esc・外側のクリックでは反映しない
- 口座・商品の小窓: 選択肢を選ぶとすぐ反映して閉じる
- キーボードでも条件を足して外せる(開いたら小窓へフォーカス、確定・Esc でトリガーのボタンに戻る)

## 6. CSV管理 `/receipts/csv?kind=…` と `/assetbalance/csv`

- 目的: 取り込む内容を確かめて保存する
- レイアウト: [一覧に戻る] 対象と保存方式(取引明細=追加、資産管理=全件置換)→ 操作バー(CSVをドラッグ、またはボタンで選ぶ → 選んだファイル名・状態・[別のファイル][保存])→ 検証結果(有効件数・エラー)とプレビュー → 保存結果 →(資産管理だけ)[AI相談文をコピー] → 区切り → 「保存済みの{対象} N件(期間)」カードに[すべて削除…]
- 削除はカードの[すべて削除…]から確認モーダルで行う(対象・件数・期間・取り消せない警告を出し、初期フォーカスは[キャンセル])。モーダルを開いた時点で保存済み件数を取り直す
- 旧URL(`/receipts/csv/delete` など)はCSV管理ページへ誘導する
- 未保存のプレビューは CSV管理の中だけに出す

## その他

- ホーム `/`: 評価額・評価損益・今年の税引後配当の短い数値欄だけ。移動は下部ナビ(機能カードは置かない)。未ログインなら案内カード(ログイン案内)だけを出す
- 銘柄検索 `/search`: 下部の検索欄 + [検索]、結果は本文
- PC: 同じページ構成。検索・条件は一覧の直上、集計と行の列を増やす。左パネルは使わない

## PC 版 取引明細 `/receipts`

- ヘッダー: ロゴ(証券Web) + グローバルナビ(ホーム/資産管理/取引明細/銘柄検索) + アカウントメニュー
- 本文: ページ名(取引明細) + 種別タブ(配当金/国内株式/投資信託) + [CSV管理]リンク → 検索バー(銘柄名・コード検索、期間セレクト、商品チップ、口座チップ、[条件をクリア]) → 集計ストリップ(3項目横並び: 配当金/税額/税引後 または 実現損益/税額/税引後) → テーブル全列表示(入金日/銘柄/口座/数量/配当金/税額/税引後 または 約定日/銘柄/口座/数量/売却金額/取得金額/実現損益/税額/税引後)
- 下部ナビなし、下部操作帯なし
- 月ごとのグループヘッダー行で件数と小計を表示

## 共通ページ枠の PC/スマホ

- ページ名(h1)は幅によらず 1 つだけ出す。スマホはページ名の右に[CSV管理]などの低頻度リンク、PC はその左隣にページ名と同じ行に入るもの(取引明細の種別タブ)を置く
- PC 幅の上部にはロゴとグローバルナビのヘッダーを出し、下部ナビと下部操作帯は隠す
