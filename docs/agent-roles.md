# エージェント役割の割り当て

**このファイルが、どのAIエージェントがどの役割を持つかの唯一の正本です。**

割り当ては頻繁に変わります。変わったら「現在の割り当て」の表だけを書き換えてください。
他のドキュメントは役割名だけで書いてあるので、書き換える必要はありません。

委譲の手順・依頼テンプレート・受け取り時の検証手順は、ユーザーレベルの
`agent-delegation` skill を正本にします(全プロジェクト共通)。

## 役割

役割名は固定です。担当が変わっても呼び方は変えません。

| 役割 | 責務 |
|---|---|
| 実装エージェント | 実装、テスト、ドキュメント更新、明示パスでの staging、作業branchへのpush、PR作成 |
| 設計エージェント | 技術選定、認証方式、外部連携、デプロイ方針の決定とレビュー |
| 統合エージェント | 実装のレビュー、PRのmerge判断とmerge実行、優先順位付け、作業分割 |

設計と統合は同じエージェントが兼ねてよいですが、**実装エージェントは自分の実装を
自分で承認しません**。

## 現在の割り当て

| 役割 | 担当 |
|---|---|
| 実装エージェント | OpenCode、Codex、Devin（モデル選択は共通 `agent-delegation` skill の該当節を参照） |

| 統合エージェント | Claude Code |

OpenCode が停止した場合は、共通 skill の「止まったときの代替」の順に切り替える。

## 実装エージェントのモデル選択

モデル選択の全プロジェクト共通の正本は `agent-delegation` skill の「OpenCodeの無料モデル選択」と「Codexのモデル選択」です。無料モデルのレート制限はアカウント単位で全プロジェクト共通であり、正本の管理元は `zaichu/agent-config` なので、ここには表や選択肢を複製しません。

このプロジェクトでは、委譲する作業を FAST / DEFAULT / DEEP に分類し、Jev の判定と並べて着手宣言に書いてください。実行者が停止して担当を切り替えるときは、元の worker を close し、Issue に切替を記録してから投げます。

### モデルに関係なく守ること

既存コードを確認してから変更する。推測で実装しない。既存の設計・規約を優先し、不要なリファクタを混ぜない。変更範囲は必要最小限。実装後に関連テストと lint / typecheck / build / test を可能な限り回す。エラーを隠すためだけの変更や一時的な回避策より、根本原因の修正を優先する。

## Issueの振り分けの補助(Jev)

Issueの規模・リスク・担当候補を Jev(TypeSafe AIのSystem One Model)で判定する。
仕組み自体は全プロジェクト共通の `issue-triage` skill が正本。
**結果は提案で、決定ではない。**

```bash
export TYPESAFE_API_KEY=<TypeSafe AIのAPIキー>   # ~/.claude/settings.json の env に置く。Gitへ入れない
~/.claude/skills/issue-triage/scripts/triage-issue.sh 867
```

共通3問(規模/リスク/担当候補)に加え、本プロジェクトでは `docs/jev-extra-questions.json` で
次の6問を追加で聞いている。

出力の形(値は見本で、実際の判定結果ではない):

```text
Issue #867 の判定 (model: jev-latest)
  規模: medium (確信度 0.71)
  リスク: low (確信度 0.83)
  担当候補: opencode (確信度 0.64)
  API契約の同期: いいえ (確率 0.12)
  マイグレーション: いいえ (確率 0.08)
  モデル分類: DEFAULT (確信度 0.70)
  段階分割: いいえ (確率 0.20)
  振る舞い固定テスト: いいえ (確率 0.15)
  UIレビュー: はい (確率 0.90)
```

### いつ回すか

- **実装を委譲する前(着手宣言の前)に必ず回す。** 規模を問わない
- 担当を切り替えて再開するときも回し直す(判定は変わらなくても、記録を残すため)

### 判定をどう使うか

| 項目 | 判定がこうなら | やること |
|---|---|---|
| モデル分類 | 統合エージェントの分類と食い違う | どちらを採るかと理由を着手宣言に書く。「必ず DEEP にするもの」は Jev に関わらず DEEP |
| 担当候補 | `claude` | 実装前に設計エージェントが方針を決める。そのまま実装エージェントへ投げない |
| 段階分割 | はい | 依頼文を段階に分け、1段階ごとにコミット・push させる(`followup` で刻む) |
| 振る舞い固定テスト | はい | 委譲前に今の振る舞いを固定するテストを用意し、「そのテストを1文字も変えずに通す」を合否条件にする |
| UIレビュー | はい | マージ前に `.claude/rules/04-frontend-ui-review.md` のスクリーンショットレビューを行う |
| API契約の同期 | はい | 依頼文に `bash scripts/check-openapi.sh` を検証コマンドとして入れる |
| マイグレーション | はい | モデル分類に関わらず DEEP |
| リスク | high | 受け取り時にセキュリティに関わる差分から読み、`security-review` skill を通す |

- 確信度が0.5未満の項目があるときは警告が出る。**モデルが迷っている合図**なので人間が判断する。
- はい/いいえの項目は確率0.5以上で「はい」と表示されるが、警告は出ない。**確率が0.3〜0.7のときは迷っている合図**として同じく人間が判断し、その判断を着手宣言に書く。
- **着手宣言のコメントに Jev の判定と統合エージェントの分類を並べて書く。** 外れが続く項目は質問文(`docs/jev-extra-questions.json`)を直す。
- 質問文を直したら、結果が分かっている過去のIssue(例: #859 UI修正、#889 依存更新、#899・#900 移植、#905 バグ修正)で回し、判定が実際と合うことを確かめてから入れる。
- `TYPESAFE_API_KEY` 未設定・API障害・想定外の応答では終了コード2で終わり、**他の作業には影響しない**。
- 送るのはIssueのタイトルと本文だけ。APIキー・接続情報・個人情報は送らない。
- **backend / frontend の実行時には組み込まない。** 外部APIへの依存を増やさないため、開発時の補助に限る。
- 外部依存のため CI には入れない。
- 質問の追加・変更方法は `issue-triage` skillを参照。
