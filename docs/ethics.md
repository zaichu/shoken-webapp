# 技術者倫理ガイドライン

本ドキュメントは、shoken-webapp の開発・運用において技術者が従うべき倫理的判断基準を定める。
機能追加・変更時には、実装前にこのガイドラインを参照すること。

## 1. データ最小化の原則

- 目的達成に必要な最小限のデータのみ収集する
- 収集理由を明示できないデータは収集しない
- 不要になったデータは速やかに削除する

### チェックポイント

- [ ] 新たに収集するデータは目的達成に必要か
- [ ] 保持期間は定義されているか
- [ ] 削除手段は提供されているか（例: アカウント削除機能）

## 2. 透明性と説明責任

- ユーザーへのデータ利用目的の明示（プライバシーポリシー参照）
- 外部サービス連携（J-Quants API、Google OAuth）はドキュメントで公開する
- ログに記録される情報の範囲を把握し、過剰なログ出力を避ける

### チェックポイント

- [ ] 外部 API 連携を追加する場合、README またはドキュメントに記載したか
- [ ] ログに個人情報・認証トークンが含まれないか確認したか

## 3. セキュリティとプライバシー設計（Privacy by Design）

- 認証・認可は実装の最初から組み込む（後付けしない）
- 機密情報（APIキー、トークン）はコードにハードコードしない
- 詳細は [`.claude/rules/02-security.md`](../.claude/rules/02-security.md) を参照

### チェックポイント

- [ ] 新エンドポイントに適切な認証ガードが付いているか
- [ ] 環境変数で機密情報を管理しているか

## 4. 公平性・アクセシビリティ

- 特定のユーザー層を不当に不利にする設計は避ける
- WCAG 2.1 AA を目標基準とする（将来的に `@axe-core/playwright` による自動監査を導入予定）
- 色のみで情報を伝えない、スクリーンリーダー対応ラベルを付与する

### チェックポイント

- [ ] 新しいUIコンポーネントに `aria-label` / `role` が適切に付与されているか

## 5. 機能追加時のレビュー観点

新機能のレビューでは、コードの正確性に加えて以下を確認する:

| 観点 | 確認内容 |
|---|---|
| データ最小化 | 不要なデータを収集・保持していないか |
| 透明性 | 外部連携はドキュメントに反映されているか |
| セキュリティ | 認証・認可・バリデーションが実装されているか |
| アクセシビリティ | 自動監査で重大違反がないか |
| ログ | 個人情報・トークンがログに出力されないか |
