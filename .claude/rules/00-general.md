# 全体開発ルール

## 言語・表現

- コードコメントは日本語
- コミットメッセージは日本語
- 変数名・関数名は英語
- コメントは原則書かない。WHY が自明でない場合(隠れた制約、直感に反する理由、特定のバグの回避)だけ1行で書く
- 作業の段階・層・Issue/PR 番号・移植元(React)との対応・コードの言い換えは書かない。それらはコミットメッセージと PR に書く

## Rust backend モジュール構成

- Rust backend では `mod.rs` を使用しない
- 親モジュールは `foo.rs`、子モジュールは `foo/bar.rs` の形で配置する
- 既存コードや設計メモで `mod.rs` を許容する記述を追加しない

## 画面の用語と書式

- 画面の用語(ラベル)と書式(金額・率・日付)は 1 か所で定義し、全画面がそれを使う
- 用語は `frontend/src/ui/labels.rs`、書式は `frontend/src/ui/format.rs` に置く
- 新しい文言は用語集に足してから使う。画面側に同じ意味の文言を書かない
- 規則の詳細は `docs/ui-design.md` の「用語と書式(全画面の共通ルール)」

## 開発フロー（標準）

### 役割分担・標準フロー
- 役割の共通運用規則の正本は agent-config の `common/AGENTS.md`（`~/.claude/CLAUDE.md` に配布）。`docs/agent-roles.md` はプロジェクト固有の割り当てを補う資料とする
- 委譲の手順・依頼テンプレート・受け取り時の検証は `agent-delegation` skill を正本とする

### タスク管理ルール
- `docs/tasks/<branch-name>.md` が存在する場合は、作業前に必ず読み、進捗とレビュー指摘を更新する
- 中規模以上のタスクでは `docs/tasks/TEMPLATE.md` を元に task file を作成する
- task file はローカルの一時ファイルとして扱い、ユーザー明示指示がない限りコミット・PR に含めない
- task file の更新は原則として対象 worktree 側で行い、main 作業ツリーへ残さない
- task 完了時または作業中止時には、対応する task file を削除する
- backend の API 契約変更時は `bash scripts/check-openapi.sh` を実行して `docs/openapi.json` を同期する
- 設計エージェントは実装委譲前に task file の実装依頼内容を最新化する
- 実装エージェントは実装前に task file のスコープ、非対象、受け入れ条件、タスク固有コマンドを確認する

- 統合エージェントはレビューとマージ判断を行い、未解消のレビュー指摘が1件でも残ればマージしない。
